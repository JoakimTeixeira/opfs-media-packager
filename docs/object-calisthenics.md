# Object Calisthenics profile

Object Calisthenics is a set of rules that keeps code small, explicit, and easy to change. The original rules were designed for object-oriented class models. This extension uses functional TypeScript with browser APIs, so it applies the intent of each rule through modules, named types, and lint rules.

| Original rule                      | Project policy                                                                                                                                          | Enforcement or evidence                                                                                            |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Keep nesting shallow               | Use guard clauses and extract focused functions. Maximum nesting is three levels.                                                                       | ESLint `max-depth`, `no-else-return`, cognitive-complexity limits, and the no-else rule.                           |
| Avoid `else`                       | Return from the handled branch, then continue with the remaining case.                                                                                  | ESLint rejects any `IfStatement` with an alternate branch.                                                         |
| Wrap meaningful primitive groups   | Use a named interface or type when values form one concept.                                                                                             | `PlaylistQueueItemContext`, `PlaylistDownloadPlan`, `PlaylistQueueState`, `VideoQualityOption`, and message types. |
| Treat collections as domain values | Keep a collection inside a named plan, scan, checkpoint, or index when it has rules beyond iteration.                                                   | `PlaylistDownloadPlan`, `PlaylistScan`, `OpfsResumeCheckpoint`, and existing-download indexes.                     |
| Keep call chains readable          | Break a chain when it hides a decision, validation step, or side effect. Standard DOM and Chrome API chains remain compact when they are one operation. | Code review rule supported by focused helper functions.                                                            |
| Use domain names                   | Name values after the product concept they represent.                                                                                                   | Ubiquitous language in interfaces, tests, UI, and documentation.                                                   |
| Keep units focused                 | A module owns one capability and a function has one operational purpose.                                                                                | `lib/` module boundaries, complexity limits, duplication checks, and dead-code checks.                             |
| Avoid mutable shared fields        | Use immutable records for data that crosses async boundaries. Keep mutable process state inside its owning coordinator.                                 | `readonly`, `Object.freeze`, `const`, and the single-writer playlist scan queue.                                   |
| Avoid accessor-heavy objects       | Prefer plain immutable values and focused functions.                                                                                                    | The domain layer has no getter or setter based model.                                                              |

ESLint enforces several syntax and complexity rules, including restrictions on `let`, `var`, `else`, nested ternaries, parameter reassignment, deep nesting, and high cognitive complexity. Those rules do not make all objects immutable. Collection ownership, domain names, module responsibilities and parameter counts need design review. The playlist queue uses `PlaylistQueueItemContext` to group related arguments.
