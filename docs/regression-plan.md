# Regression protection plan

This plan records the work required to detect a change that breaks an existing user workflow. A test verifies one specified behaviour. No finite suite guarantees that every possible regression is found.

| Stage                        | Behaviour to protect                                                                                                                          | Evidence and status                                                                                                                                                                         |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Track queue decisions     | Stop after two consecutive access failures, stop on a classified host limit or engine failure, and continue after an individual item failure. | The queue policy tests in `tests/` check decisions. Browser tests cover two denied items, cancellation and retry. Other failure sequences still need review.                                |
| 2. Browser boundaries        | Selected reusable rules must not directly access Chrome, window or document properties.                                                       | The architecture tests in `tests/` check selected browser-global access and prevent library imports of extension entry points. Aliases and indirect dependencies remain outside this check. |
| 3. Media correctness         | Output should preserve expected duration, resolution, audio and video alignment, and chosen subtitle track.                                   | Partial. Synthetic MP4 and MKV files have decodable audio and video. The MKV subtitle text and default flag are checked. Long-video synchronization remains untested.                       |
| 4. Download recovery         | Cancellation at each stage, missing or corrupt temporary parts, expired access, and retry must preserve the appropriate state.                | Partial browser and unit tests exist in `tests/e2e/` and `tests/`. Audit each scenario before adding tests.                                                                                 |
| 5. Playlist and site changes | Detect page navigation, all available qualities, captions, and track topics across representative anonymized structures.                      | Partial integration and browser tests exist. Real-site layout and login changes remain outside the automated fixtures.                                                                      |
| 6. Mutation scope            | Tests should detect small deliberate defects in each extracted decision.                                                                      | Queue policy joins the modules in `stryker.config.mjs`. Expand only after the relevant logic has independent tests.                                                                         |

Run `npm run verify` for the release checks and `npm run test:mutation` separately. Keep the results and explain any failing or unexecuted checks when delivering a release.
